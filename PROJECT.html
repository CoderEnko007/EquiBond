一、项目概述

1.1 这个系统回答什么问题

一个最朴素的资产配置问题：当下这笔钱，放股票好还是放债券好？

债券有明确的"票面利息"，一眼就能看到收益率；股票没有——但它有盈利。把市盈率倒过来看，就得到一个可以和债券收益率直接放在同一刻度上比较的数字。

于是整个决策被压缩成一个差值：

text
盈利收益率  E/P  = 100 / PE(TTM)              ← 股票的隐含"投资回报率"
无风险收益率 Y10 = 10 年期国债到期收益率        ← 债券的"利息"

股权风险溢价 ERP = E/P − Y10                   ← 承担股票风险换来的额外补偿
ERP 状态含义系统给出的动作
处于历史高位（> +1σ）股票相对债券很便宜，补偿丰厚超配股票（默认最高 90%）
处于中性区间（±1σ）两者性价比接近维持基准比例
处于历史低位（< −1σ）溢价被压缩，债券的确定性更有吸引力减配股票（默认最低 20%）

这就是全部逻辑。 剩下的工作是把这条主线做严谨：用真实数据算、把绝对值换成历史分位、把分位映射成仓位、用一个不含未来函数的框架回测它。

1.2 设计原则

原则具体体现
只用真实数据全部是 Wind / 交易所口径的真实历史序列，没有任何随机数或模拟数据
纯静态、零依赖运行看页面不需要 Node、不需要 Python、不需要联网，双击 HTML 即可
可复现数据全部落盘为 CSV，任何人用同样的 CSV 跑同样的脚本得到同样的结果
防未来函数严格用 t−1 期信号决定 t 期仓位（详见 5.6）
计算与展示分离engine.js 是纯函数无 DOM，可在 Node 里直接单测；app.js 只负责渲染
参数全暴露信号口径、回看窗口、映射方式、仓位区间、再平衡频率、成本全部可调，改了立刻重算

4.2 build_dataset.py 的对齐规则

python
# 1. 估值：同月多条取最后一条（月末值）
val_by_month[month_key(d)] = {...}   # 后写覆盖

# 2. 价格：同上
px_by_month[month_key(d)] = {...}

# 3. 收益率：日频 → 取每月最后一条观测
yld_by_month[month_key(d)] = {...}

# 4. 面板骨架 = 三个源的月份并集（且 ≥ 2011-01）
# 5. ok = 1 当且仅当 pe / div / close / y10 四项齐全

为什么要保留 ok=0 的月份？ 因为收益率计算需要用前一行做分母。如果直接把不可用月份删掉，会产生虚假的相邻关系，导致某个月的收益率被算成横跨两个月。buildSeries 内部会跳过 ok=0 的行，但 prev 仍然取原始行的上一行，所以 ok=0 的月份只会被跳过、不会被"跳接"。

4.3 dataset.js 结构

js
window.EQBD = {
  meta: {
    generated: "2026-10-27 16:41:22",
    index: "沪深300 (000300.SH)",
    valuation_source: "Wind 指数加权口径 PE/PB/股息率(月末最后交易日)",
    yield_source: "银行间国债收益率曲线 10年期(月末最后交易日)",
    months_total: 185,
    months_usable: 178,
    range: ["2012-01", "2026-10"],
    daily_count: 3581,                       // 日频面板交易日数
    daily_range: ["2012-01-31", "2026-10-27"],
    daily_source: "新浪财经日线 × Wind 月末 PE 锚点推算",
    latest: { date, pe, pb, div, y10, close },
    refresh: {            // 由 update.py 追加，build_dataset 单独跑时不存在
      refreshed_at, anchor_date, anchor_age_days, anchor_expired,
      live: { date, close, source }, y10_source, changes
    }
  },
  rows:  [ { m, d, pe, pb, div, close, y10, y1, y30, ok }, ... ],
  daily: [ ["2026-10-28", 12.87, 1.6345, 4083.87, 166.6], ... ]  // [日期, PE, Y10, 收盘, 成交量(亿股,可选)]
};

日频面板 daily 的来历： PE = 总市值 / 总盈利。月内盈利不变，PE 与收盘价严格成正比，所以每个交易日 PE_t = 最近一个 Wind 权威日 PE × Close_t / Close_锚点日；跨月（尤其 4/8/10 财报季）盈利跳变时，新的权威日自动重新锚定，误差不会累积。Y10 直接用日频序列，当日未发布（17:30 后才有）时沿用前一交易日。这个序列就是图表的日频形态，也是 20 日均线平滑信号的原料。第 5 位是成交量（亿股，新浪日线自带），供「买卖信号」板块的量能情绪指标使用，旧数据无此位时前端自动兼容。

为什么用 JS 而不是 JSON？ 因为 JSON 用 fetch 加载在 file:// 协议下会被 CORS 拦截。写成 <script> 赋值语句，双击 HTML 就能用。

5.2 buildSeries —— 派生指标

对每一行计算：

js
ep       = 100 / pe                 // 盈利收益率 %
erp      = ep - y10                 // 差值式信号
ratio    = ep / y10                 // 比值式信号
dyspread = div - y10                // 股息式信号

股票端月收益：retEq

js
retEqPrice = close_t / close_{t-1} - 1
retEq      = retEqPrice + div_{t-1} / 100 / 12

为什么加股息： 沪深300 的月线收盘是价格指数，不含分红。为了做总收益口径的回测，补上月股息率的 1/12 作为再投资近似。这是近似而非精确（真实除息日的分红现金再投资会有微小差异），但对月度频率的策略判断影响很小。

债券端月收益：retBd

js
carry = y10_{t-1} / 100 / 12            // 持有一个月的票息收入
Δy    = (y10_t - y10_{t-1}) / 100       // 收益率变动
retBd = carry - D_mod × Δy              // 票息 + 资本利得

原理： 债券总收益 ≈ 票息收益 − 修正久期 × 收益率变动。久期衡量价格对利率的敏感度，所以利率下行（Δy<0）时债券净值上升，−D×Δy 为正。这个方法把一条收益率曲线序列合成成了"持续持有 10 年期国债并每月滚动"的总收益指数，覆盖了票息和价格波动两部分。

修正久期推导

js
function modDuration(yieldPct) {
  const N = 10, m = 2, n = N * m;              // 10 年期，半年付息，20 期
  const y = yieldPct / 100;
  if (y <= 1e-6) return N;                      // y→0 时久期趋于期限本身
  const i = y / m;                              // 每期折现率
  const dPeriods = ((1 + i) / i) * (1 - Math.pow(1 + i, -n));  // Macaulay 久期（期）
  return dPeriods / (1 + i) / m;                // ÷(1+i) 得修正久期，÷m 换成年
}

校验：YTM=2.0% → D≈9.00；YTM=4.0% → D≈8.09。符合"10 年期平价国债修正久期在 8~9 之间"的常识。

5.3 rollingStats —— 滚动标准化

js
start  = window > 0 ? max(0, i - window + 1) : 0     // 0 表示扩张窗口（全样本）
sample = series[start..i] 中该字段的非空值
mean   = 算术平均
sd     = 样本标准差（n−1 分母）
pct    = percentileRank(sample, x)   // 样本中 ≤ 当前值的占比
z      = (x − mean) / sd

两种窗口模式的差异很重要：

模式window 值特点
扩张窗口0从样本起点算起，早期样本少、噪声大；后期稳定但反应迟钝
滚动窗口120 / 60 / 36固定回看 N 个月，自适应估值中枢下移，推荐默认用近 10 年

为什么推荐滚动窗口： A 股估值中枢在 2012→2026 年间系统性下移（PE 从 11~12 倍区间降到 10 倍出头）。用全样本算分位，会把十年前的"贵"当成现在的"正常"，导致分位系统性偏高。滚动 10 年窗口能追踪这种漂移。

5.4 equityWeight —— 信号 → 仓位

js
if (map === 'pct')  t = clamp(p, 0, 1);                              // 历史分位
else                t = (clamp(z, -zRange, zRange) + zRange) / (2*zRange);  // Z 截断
w = clamp(minW + (maxW - minW) * t, 0, 1);
映射方式优点缺点
历史分位线性（默认）稳健，不受极端值影响，分布自适应在震荡市中分位容易到两端，信号偏"躁"
Z-Score 截断保留了偏离幅度信息，中间区域更平缓受厚尾分布影响，需要 zRange 截断（默认 ±2σ）

minW / maxW 的作用是避免全仓进出——即使信号极端，也保留至少 20% 的反向资产，这在实盘中能显著降低犯错成本。默认值 20% / 90%。

5.6 backtest(series, cfg) —— 回测

这是整个系统最需要严谨的地方。 核心是这一行：

js
} else if ((i - startIdx) % (cfg.rebalance || 1) === 0) {
  const st = rollingStats(series, i - 1, cfg.window, cfg.signal);   // ← i-1！
  w = equityWeight(st.pct, st.z, cfg);
}
const ret = w * r.retEq + (1 - w) * r.retBd - cost;

时序链：signal(t−1) → weight(t) → return(t)

调仓发生在第 t 期期初，使用的是第 t−1 期（已收盘）观测到的信号值。如果不做这个滞后，就相当于"知道今天收盘后的 ERP 再决定今天的仓位"，回测结果会漂亮得离谱但完全无效。

信号值默认取 20 日均线平滑后的 ERP（cfg.smooth: true）。日频 ERP 的单步变动里噪声占比很高（穿越均线次数是月频的 7.8 倍），直接用月末单日值相当于掷一次骰子定仓位；20 日均线（约一个月）平滑后，信号更稳且换手更低——实测对比：平滑后年化 8.19% / 换手 6.2%，未平滑 7.82% / 7.2%。参数面板可随时关掉平滑回到原口径。

  2. 数据延迟对照表：模拟"对方的图截止在 1/2/3/6/9/12 个月前"，列出当时的读数与当时口径下的 z。这是最常见的差异来源：2026 年 6~10 月沪深300 回调 17.8%，ERP 从 5.16 抬到 6.11——截止在 2026-04 的图 z 恰好 = 0.00（贴着均线），而更新到 10 月就是 +0.98。

7.2 PE 的滚动推算

这是整个更新机制的核心，也是它"不算作弊"的原因。

在同一份财报的有效期内，指数每股盈利 E 是常数，而 PE = P / E，所以：

text
PE_today    = PE_anchor × (Close_today / Close_anchor)
PB_today    = PB_anchor × (Close_today / Close_anchor)
股息率_today = 股息率_anchor × (Close_anchor / Close_today)

股息率反向是因为分红金额固定，价格上涨则收益率下降。

这是数学恒等，不是拟合、不是估算。 关键点：

  1. 永远从原始锚点起算 —— 脚本每次都从 CSV 末行（锚点）直接推算到今天，不逐次叠加，因此不存在漂移累积。
  2. 锚点价格取自同日期 —— 优先用 hs300_price_monthly.csv 中与锚点同日的价格；找不到时退化为锚点所在月的最后收盘。
  3. 月度 upsert —— month_upsert() 保证一个自然月永远只有一条记录（该月最新观测）。同月内多次运行只会覆盖，不会产生重复月度数据点。

实测锚点①：2026-10-23 Wind 给出 PE=12.8222，推算至 2026-10-26 得 PE=12.846，与 Wind 口径完全自洽。

7.3 财报期失真与 calibration.json

唯一会失真的情况：跨过财报披露期。 沪深300 的成分股盈利 E 大致在 4 月底 / 8 月底 / 10 月底 附近更新，此时即使价格没变，PE 也会跳变，滚动推算立即失效。

为此设计了双日期机制：

日期存放位置语义谁会更新它
anchor_dateCSV 末行的日期当前数据点每次运行 update.py 都会刷新
calibrated_atdata/raw/calibration.json上次用 Wind 权威源写死 PE 的日期只有加 --calibrate 才会刷新

为什么必须分开： 如果脚本自己每次更新都刷新"校准日期"，那么"距今多少天"永远归零，过期检查就永远命中不了，形同虚设。

阈值 ANCHOR_MAX_AGE = 110 天（约一个季报周期 + 缓冲）。超过时：

  • 运行时打印红色警告；
  • 页面顶部弹红色提示条（meta.refresh.anchor_expired = 1）。

到期的处理（任选其一）：

  1. 在 WorkBuddy 里对我说 「校准股债数据」 —— 我用 Wind MCP 重新取一次 PE/PB/股息率，覆盖 CSV 末行，再带 --calibrate 运行；
  2. 手工改写 hs300_valuation_monthly.csv 末行的 pe,pb,div，然后： `bash python scripts/update.py --calibrate `

口径公式适合场景特点

9.2 敏感性规律

经过实测，参数对结果的影响大致如下：

参数调大的效果
window（回看窗口）更稳定、更迟钝；短窗口（3 年）更敏感但容易产生假信号
minW / maxW 区间收窄年化和回撤同步下降，夏普通常先升后降
rebalance 拉长换手下降、成本下降，但信号响应变慢
costBp 提高年化线性下降；月度再平衡下 5bp→20bp 会明显侵蚀超额
信号口径切换结论方向通常一致，但极端程度不同（比值式最激进，股息式最保守）

9.3 警惕过拟合

页面上的参数可以组合出几百种回测结果。不要挑那个最好看的——那几乎一定是过拟合。判断标准应该是：

  • 相邻参数下结果是否稳定（把 window 从 120 挪到 96、144，结论是否翻转？）
  • 换一种信号口径，方向是否一致？
  • 加了成本以后优势还剩多少？
  • 分两段子样本（如 2012-2018 / 2019-2026）分别跑，是否都成立？

  • 不做择时的全部 —— 没有考虑宏观流动性、政策、盈利周期位置等 ERP 之外的因素。

更新数据的最小流程

text
每个月（或每次想刷新）：
    双击 start.bat
    ↓
    新浪/东财拉最新收盘 → 按锚点推算 PE/PB/股息 → 写回 CSV
    ↓
    调 build_dataset.py 重建 panel
    ↓
    写 meta.refresh（含新鲜度、锚点年龄）
    ↓
    自动打开 index.html

每跨过一个财报期（4/8/10 月底）：
    对我说「校准股债数据」（或手工改 CSV 末行）
    ↓
    python scripts/update.py --calibrate
